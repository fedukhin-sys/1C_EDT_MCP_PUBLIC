# Грабли BSL / 1С — наработки боевых задач

Проверенные на живых конфигурациях (УТ 11.5, БСП) ловушки. Читать перед написанием BSL-кода,
ручной правкой `.mdo`/`.form` и печатными формами.

## BSL: язык

- **Нет встроенных `Abs`/`АБС`/`Знак`/`Sign`** («Процедура или функция не определена»). Есть `Pow`, `Sqrt`, `Log` (натуральный), `Exp`, `Цел`, `Окр`. Модуль: `?(x < 0, -x, x)`; знак: `?(x < 0, -1, ?(x = 0, 0, 1))`. Другие матфункции перед использованием проверять grep'ом по реальному .bsl, не по памяти.
- **`И` и `Знач` — зарезервированные слова**, НЕ использовать как имена переменных (в т.ч. `Для Каждого Знач Из …`). EDT `check_run` это ПРОПУСКАЕТ, а runtime 1С падает «Ожидается имя переменной».
- **`Вычислить(...)` — только функция в выражении**; для вызова процедуры строкой — оператор `Выполнить(...)`. «CommonModule.X.Метод()» — MD-ссылка, не callable: для `Выполнить` нужно «X.Метод()».
- **Цепочка от конструктора недопустима**: `Новый Запрос(Текст).Выполнить()` → «Неопознанный оператор»; валидатор `write_module` (`validated:true`) это НЕ ловит, платформа падает при компиляции модуля. Всегда промежуточная переменная.
- **`ТекущаяДата()` устарела везде.** Сервер/толстый клиент/внешнее соединение → `ТекущаяДатаСеанса()`; тонкий/web-клиент → `ОбщегоНазначенияКлиент.ДатаСеанса()` (глобальной `ТекущаяДатаСеанса` там нет — runtime-блокер на web, хотя EDT метит только info).

## Расширения

- **Сигнатура override 1:1**: при `&ИзменениеИКонтроль`/`&Перед`/`&После`/`&Вместо` сигнатура процедуры расширения обязана совпадать с базовой 1:1 (параметры, порядок, дефолты). Для `&ИзменениеИКонтроль` тело = полный текст оригинала + `#Вставка/#КонецВставки` (`#Удаление/#КонецУдаления`); стаб без оригинала = замена пустотой. Workflow: `read_module` базового → скопировать сигнатуру и тело → вставки.
- **ЛЮБЫЕ правки внутри тел `&ИзменениеИКонтроль`** (даже `ЭтаФорма`→`ЭтотОбъект`) дают error «Текст метода имеет отличия от базового» — mass-replace-скрипты обязаны пропускать эти зоны.
- **`&Вокруг` в расширениях-адаптациях запрещён** (корпоративный стандарт этого проекта): только `&Перед`/`&После`/`&ИзменениеИКонтроль`.

## Ручная правка Form.form (XDTO)

deploy падает «Несоответствие свойства и элемента данных XDTO: Свойство 'Type'» — и `check_list_markers` это НЕ ловит:
- у `form:Button` порядок узлов строгий — `name→id→visible→enabled→userVisible→extendedTooltip→commandName→…` (commandName ДО extendedTooltip = падение);
- у `form:Table` НЕТ `<extInfo>` — все свойства прямо в элементе.

## Скрипты/regex над BSL-кодом

- **JS regex `\b` НЕ работает с кириллицей** (даже с /u) — использовать `(?![\p{L}\p{N}_])` для границы после идентификатора.
- Правила `#Область`: при нескольких top-level `#Если` блоках `#Область` — ВНЕ всех `#Если` (`#Область ⊃ #Если ⊃ Процедура`); аннотация `&НаКлиентеНаСервереБезКонтекста` ПЕРЕД `#Если` — compile-блокер (переносить внутрь блока); `КонецПроцедуры` бывает inline с `КонецЕсли;` — учитывать в поиске.
- Inline-suppression (`//@skip-check`, `// BSLLS:...-off`) EDT-валидатор НЕ признаёт.

## Печать: .mxlx и ТабличныйДокумент

- **`<i>N</i>` в ячейке .mxlx = ИНДЕКС колонки** (0-based, для разреженных строк), НЕ span — `<i>` для «объединения» теряет контент. Объединение = отдельная запись `<merge><r>строка0based</r><c>колонка0based</c><w>ДОП_колонок</w>[<h>доп_строк</h>]</merge>` ПОСЛЕ vgRows, ПЕРЕД namedItem (col0+col1 → `<c>0</c><w>1</w>`).
- Сумма ширин колонок ≤ ~820 ед. для одной портретной страницы; `АвтоМасштаб=Истина` горизонтальный разрыв НЕ устраняет.
- **`АвтоМасштаб = Истина` ужимает лист под ОДНУ страницу целиком** (ширина+высота) — высокий документ станет микроскопическим. Свойства «ПоШиринеСтраницы» НЕТ. Печать «по ширине»: `АвтоМасштаб = Ложь` + фиксированный `МасштабПечати` (%, стабильно при детерминированных ширинах колонок).
- `РазмерБумаги = ТипРазмераПечати.A4` — ошибка компиляции, не использовать.

## Headless-работа с .epf и клиентом

- Неподписанный .epf → модальная «Защита от опасных действий» ломает headless (`/Execute`, `Подключить()`, загрузку в БСП) — добавлять в доверенные или просить пользователя отключить предупреждение.
- `1cv8 ENTERPRISE /Execute` запускать ТОЛЬКО с `-RedirectStandardError <файл>` (иначе падение «Char 0x0 out of allowed range» на старте).

## Операционка xUnit / MCP-сессии

- Рестарт EDT/переустановка плагина рвёт SSE-сессию клиента — все инструменты таймаутят; лечится только `/mcp` → Reconnect на стороне клиента (Restart сервера в EDT не помогает).
- Если прогон висит дольше пары минут — СРАЗУ `query_event_log` (severity Error): событие `_$PerformError$_` даёт точную строку BSL-ошибки; молчаливый exit=1 без result-файла = compile-ошибка раннера.
- После create/мутаций через BM `.mdo` появляется на диске асинхронно (~100–1500 мс, инструменты v1.10.2+ сами поллят FS с backoff 50→1600 мс) — при ручной работе с файлами сразу после мутации перепроверить наличие/содержимое файла; не рестартовать EDT в это окно (BM-only объекты теряются).
